# Локальный протокол v1

Native engine: `ws://127.0.0.1:8742`; web assets внутри приложения: `http://127.0.0.1:8743`. Серверы слушают только loopback. Никакой авторизации по одному лишь origin нет: требуется случайный session token, создаваемый при запуске.

Для отдельного редактора разработчик может запустить:

```sh
npm run dev
native/.build/release/neural-light-engine --port 8742 --print-url
```

Откройте выведенный URL локально. Токен не следует включать в логи, скриншоты или публиковать. После завершения движка он недействителен. Desktop-оболочка передаёт его редактору автоматически.

## JSON client → engine

Первое сообщение в течение 3 секунд:

```json
{"type":"auth","token":"SESSION_TOKEN"}
```

Ответ: `{"type":"hello","version":1,"backend":"native"}`. Неверный токен закрывает соединение. Максимум 4 клиента, 1 MiB на сообщение.

Дальнейшие команды:

```json
{"type":"scene","scene":"полный объект из examples/aurora.json"}
{"type":"seek","time":12.5}
{"type":"ping","time":12345.67}
{"type":"controllers","controllers":[]}
```

`scene` выше показан схематически: в настоящем сообщении это объект, не строка. Граф компилируется редактором в `layers`; движок валидирует и исполняет эти слои. `graph` в сохраняемых файлах описывает редактируемые узлы и позиции. При импорте редактор заново компилирует граф.

Команда `scene` также принимает необязательное поле `transitionMs` (число 0–600). Выбор готовой/сохранённой сцены передаёт 450 мс: последний показанный RGB-кадр плавно смешивается с живым новым эффектом. Повторный выбор начинает переход с текущего смешанного кадра. Обычные правки без поля сохраняют текущий переход; `0` отменяет его. Нулевая яркость и изменение количества/расположения LED отменяют переход. Reduce Motion передаёт `0`. Preview и UDP получают один и тот же смешанный результат; время смешивания входит в `renderMs`.

Пример контроллера:

```json
{"id":"desk","name":"Стол","host":"192.168.1.50","count":240,"offset":0,"protocol":"ddp","enabled":true,"latencyMs":12,"budgetKbps":2000}
```

Список controllers заменяется целиком. Несуществующие/выключенные отправители закрываются. Повторяющиеся id, неверные диапазоны, неизвестные эффекты и нечисловые параметры отклоняются. Ошибка возвращается как `{"type":"error","message":"..."}`; отказ от аудиодоступа дополнительно сообщает `source:"demo"`.

## Binary engine → editor

Каждый preview frame имеет 16-байтовый заголовок:

| Смещение | Формат | Содержимое |
|---|---|---|
| 0 | ASCII 4 bytes | `NL01` |
| 4 | uint32 little endian | sequence |
| 8 | uint32 little endian | LED count |
| 12 | float32 little endian | время сцены, секунд |
| 16 | uint8 RGB × count | цвета в порядке физической адресации |

`sequence` переполняется модулем 2³². Время сцены следует паузе/seek; время аудиозахвата основано на монотонных часах хоста. Не сравнивайте native uptime и browser performance.now напрямую.

## Телеметрия

JSON примерно 10 Hz: `type`, `fps`, `renderMs`, `audioAgeMs`, `elapsed`, `frames`, `dropped`, `backend`, `features`, `devices`.

- `renderMs`: для Metal — от подготовки/submit до обработанного завершения GPU, включая dispatch callback; для CPU — вычисление кадра. FFT не входит в Metal-таймер. Это не GPU-only timestamp.
- `audioAgeMs`: возраст последнего аудиобуфера до FFT; 0 в demo. FFT-окно добавляет 2048/sampleRate секунд контекста, не включённых в это число.
- `dropped`: кадры движка, пропущенные из-за занятого GPU или смены снимка сцены.
- `features`: 48 bands, bass/mid/high, rms, beat envelope, bpm (0 до достоверной оценки), capturedAt.
- `devices`: id, sent, dropped, fps (целевой лимит), sendMs, status.
- `pong.time` повторяет значение `ping.time`; редактор вычисляет RTT на собственных часах.

При медленном клиенте preview frames пропускаются. Телеметрия хранится одним последним сообщением; важные текстовые ответы имеют очередь максимум 8. На стороне UDP у каждого устройства один ожидающий кадр, общая калибровочная история ограничена 64 кадрами.
