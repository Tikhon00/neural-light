# NEURAL LIGHT NODE — своя прошивка ESP32

Это отдельная прошивка нашего проекта, а не настройка или форк WLED. Mac считает звук и эффекты, ESP32 принимает готовые RGB-кадры и передаёт их на ленту. WLED на плате не требуется.

**[Открыть веб-установщик](https://tikhon00.github.io/neural-light/)**

Версия 0.1.0 Preview. Код собирается для ESP32, приёмник пакетов и интерфейс проверяются автоматически. Физической платы у разработчика нет: загрузку, Wi-Fi и настоящий свет должен проверить владелец оборудования.

## Что поддерживается

| Часть | Первая версия |
|---|---|
| Плата | Обычный ESP32 DevKit / ESP32-WROOM, 4 МБ flash |
| Другие ESP | S2, S3, C3, C6, ESP8266 и WROVER с PSRAM пока не входят в эту сборку |
| Лента | WS2812B или SK6812 RGB, 800 кГц, 1–1024 светодиода |
| Порядок цветов | GRB или RGB; RGBW не поддерживается |
| Wi-Fi | Сеть 2,4 ГГц; Mac и контроллер в одной локальной сети |
| Приём кадров | DDP-профиль NEURAL LIGHT, UDP 4048 |
| Настройки | Локальная веб-страница на плате, сохранение в NVS |
| Потеря кадров | Через 2 секунды без целого кадра лента гаснет |

Если маркировка платы отличается, сначала уточни модель. Установщик распознаёт семейство чипа, но не проверяет конкретную разводку GPIO, размер flash и подключение питания.

## Серёга, как установить

1. На компьютере открой установщик в Chrome или Edge. iPhone подходит для просмотра страницы, но не для прошивки этим способом.
2. Для первой прошивки отключи питание ленты. Подключи ESP32 кабелем USB **с передачей данных**. Закрой другие программы, которые заняли её serial-порт.
3. Прочитай совместимость и подтверди замену прошивки. Нажми «Подключить ESP32», выбери порт своей платы и установи NEURAL LIGHT NODE.
4. Установка заменяет **прошивку и настройки**, включая прежние данные WLED. После каждой установки полного бинарника Wi-Fi и LED нужно настроить заново.
5. Если подключение зависло на соединении, удерживай BOOT на своей плате, повтори подключение и отпусти BOOT после начала записи. Не отключай USB во время записи.

Страница не запрашивает порт и не начинает прошивку самостоятельно. При ошибке загрузки бинарника кнопка установки недоступна. Неподдерживаемый чип не получает образ для ESP32.

## Настроить Wi-Fi и ленту

После установки в окне ESP Web Tools открой **Logs & Console**, введи `INFO` и нажми Enter. Скорость serial — **115200**. Прошивка покажет имя сети вида `NEURAL-LIGHT-A1B2C3` и индивидуальный пароль этой платы.

1. Подключи Mac к этой сети платы, используя показанный пароль.
2. Открой [http://192.168.4.1/](http://192.168.4.1/). Интернет для этой страницы не нужен.
3. Укажи домашний Wi-Fi, пароль, GPIO контакта DATA, число LED и порядок цветов. По умолчанию предложены GPIO 16, 240 LED, GRB и лимит яркости 25% — проверь их по своему подключению.
4. Подтверди, что проверены проводка, питание и общая земля; нажми «Сохранить и подключить». До первой сохранённой настройки прошивка не запускает LED-вывод.
5. Страница покажет IP контроллера в домашней сети. Запиши его. Сеть настройки остаётся доступной ещё около двух минут, чтобы успеть увидеть адрес.
6. Верни Mac в домашнюю сеть. Настройки платы теперь открываются по её IP или `http://neural-light-XXXXXX.local/` — точное имя видно через `INFO`.

Для DATA разрешены GPIO **13, 14, 16, 17, 18, 19, 21, 22, 23, 25, 26, 27, 32, 33**. Это номера GPIO, а не порядковые номера ножек. Ленте нужен блок питания подходящего напряжения и мощности; GND платы и ленты должны быть соединены. Процент яркости — не измеритель тока и не замена расчёту питания.

Пароль домашнего Wi-Fi не возвращается веб-странице и не печатается в логах. Пароль сети настройки доступен через USB-команду `INFO`. Если сеть настройки выключена, команда `SETUP` снова включает её и приостанавливает LED-вывод до повторного сохранения настроек. Если подключиться к домашней сети не удалось за 30 секунд, включается сеть восстановления.

## Запустить свет с Mac

1. Открой собранное **NEURAL LIGHT.app**, выбери эффект и поставь небольшую яркость.
2. В «Ещё → Расположение LED» задай число LED сцены. Для первого прогона используй одну ленту.
3. Нажми «Подключить свою → Добавить контроллер». Введи IP платы и её число LED.
4. В «Настройках устройства» выбери **DDP · 4048**, «Первый LED сцены» — 0. Включи «Передавать свет».

**Число LED устройства на Mac и на ESP32 должно совпадать.** NODE показывает только собранный целый кадр. Если на плате указано 240, а Mac передаёт 100 LED, частичный кадр будет отвергнут. Общая сцена Mac может быть больше: для нескольких плат выбирай разные диапазоны сцены, но число LED каждого устройства должно соответствовать его плате.

В веб-странице платы раскрой «Состояние контроллера»: там реальные счётчики приёма и вызовов вывода, пропущенные кадры, ошибки и частота вывода. Это не фотодиодный замер и не подтверждение того, что все физические светодиоды исправны.

У WS2812 передача занимает примерно 30 мкс на RGB-светодиод. Поэтому 60 FPS на Mac не означают 60 FPS на длинной последовательной ленте: для 1024 LED только передача уже занимает около 31 мс. Прошивка хранит последний целый кадр и не накапливает очередь на показ.

## Проверка на реальном устройстве

- После чистой установки вывод выключен до настройки GPIO и LED.
- После настройки проверь 10–20 LED на малой яркости; затем переходи к полной длине.
- Проверь красный, зелёный и синий; при перепутанных цветах переключи GRB/RGB.
- Установи одинаковое число LED на Mac и плате, включи DDP и сравни счётчики приёма/вывода.
- Останови отправку на Mac: в течение примерно двух секунд лента должна погаснуть.
- Отключи и верни Wi-Fi; проверь восстановление, `INFO` и `SETUP`.
- Перезагрузи плату: настройки должны сохраниться. После перепрошивки полного образа они, наоборот, сбрасываются.

Не помечай эти проверки выполненными только по успешной компиляции. Общий план аппаратного прогона — [HARDWARE-CHECK.md](HARDWARE-CHECK.md).

## Для его Codex: сборка и изменения

Все команды — из корня репозитория. Для инструментов прошивки нужен Python; CI использует Python 3.12.

```sh
python3 -m venv .venv-firmware
source .venv-firmware/bin/activate
python -m pip install -r firmware/requirements.txt
npm ci
npm run firmware:test
npm run firmware:build
npm run firmware:export
npm run installer:build
npm run installer:dev
```

Открой `http://127.0.0.1:5174/`. Экспорт объединяет bootloader, таблицу разделов, boot_app0 и приложение в один `.bin` для классического ESP32: DIO, 40 МГц flash, 4 МБ. Ничего на подключённую плату эти команды не записывают.

Зависимости закреплены: PlatformIO 6.2.0, platform-espressif32 6.12.0 / Arduino 2.0.17, Adafruit NeoPixel 1.15.4, esptool 4.11.0, ESP Web Tools 10.5.2. Сгенерированные файлы находятся в `installer/public/firmware/`; бинарники, manifest, SHA-256 и metadata публикуются вместе со страницей, но не коммитятся в Git.

| Что менять | Файл |
|---|---|
| Wi-Fi, NVS, GPIO, LED, UDP и локальный HTTP | `firmware/src/main.cpp` |
| Страница настройки на самой плате | `firmware/include/SetupPage.h` |
| Проверка пакетов, сборка целого кадра и таймаут | `firmware/include/FrameReceiver.h` |
| Тесты без платы и пакеты от Mac | `firmware/tests/`, `firmware/test-receiver.sh` |
| Модель платы и библиотеки | `firmware/platformio.ini` |
| Версия образа | `firmware/version.txt` и `NEURAL_FIRMWARE_VERSION` в `platformio.ini` — менять вместе |
| Публичный установщик | `installer/index.html`, `installer/src.ts`, `installer/styles.css` |
| Объединение образа и manifest | `scripts/export-firmware.py` |
| Автоматическая проверка и публикация | `.github/workflows/firmware.yml` |

Проверки интерфейса: `npm run installer:test` с Chrome на Mac; CI ставит Chromium. Они не открывают USB и не прошивают устройство. Тесты приёмника собираются C++11 с AddressSanitizer и UndefinedBehaviorSanitizer. При доступном `swiftc` проверяется, что fixture совпадает с настоящим `Packets.swift`.

Приёмник поддерживает **профиль нашего отправителя**: DDP v1, RGB type 1/display 1, 1–15 sequence на целый кадр, PUSH на последнем диапазоне, максимум 1440 байт payload в пакете. Весь настроенный диапазон должен быть покрыт. Sequence 0, timestamp, частичные обновления и отправители с sequence на каждый пакет не поддерживаются. Четыре бита sequence не обеспечивают защиту от произвольного replay; это протокол для доверенной локальной сети, не аутентификация.

HTTP на плате: `GET /`, `GET /api/config`, `GET /api/status`, `POST /api/config`. Сохранение требует token из локальной страницы и допустимый Host/Origin; тело ограничено 1024 байтами. Нет cloud API, удалённого OTA, DNRGB, самостоятельных эффектов на плате или RGBW. Изменять HTTP-формат нужно вместе со страницей настройки.

При push в `main` workflow проверяет приёмник, собирает ESP32 и установщик, выполняет browser-тесты и публикует GitHub Pages только после успеха. Pull request выполняет проверки без публикации. GitHub Releases и скачиваемые архивы не создаются.

Источники для следующих изменений: [ESP Web Tools: manifest и объединение образов](https://esphome.github.io/esp-web-tools/), [Espressif: esptool](https://docs.espressif.com/projects/esptool/en/latest/esp32/esptool/basic-commands.html), [PlatformIO: ESP32 Dev Module](https://docs.platformio.org/en/latest/boards/espressif32/esp32dev.html), [Adafruit NeoPixel](https://github.com/adafruit/Adafruit_NeoPixel).
