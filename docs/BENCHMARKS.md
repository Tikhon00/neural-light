# Измерения и проверка

Дата: 14 ноября 2026. Apple M5, macOS 26.6.2, arm64. Нативная release-сборка, Swift 6.4.2; браузер — установленный Chrome. В фоне было открыто приложение, это короткий воспроизводимый smoke benchmark, не длительный нагрузочный или тепловой тест.

## Нативный движок

На каждое число LED: 0,7 с прогрева, 3 с сбора, 27–28 телеметрических измерений. Общий render clock 60 Hz; кадры отправляются в локальный WebSocket, настоящий ESP32 не подключён.

| LED | Средний FPS | Рендер p50, мс | Рендер p95, мс | Пропуски, накопительно |
|---:|---:|---:|---:|---:|
| 240 | 59.99 | 0.569 | 1.193 | 0 |
| 1,000 | 60.01 | 0.515 | 1.459 | 0 |
| 4,096 | 60.05 | 0.721 | 1.669 | 0 |
| 8,192 | 59.98 | 0.888 | 1.640 | 0 |

`renderMs` измеряет подготовку и выполнение Metal-команды до completion callback на очереди движка. Это не чистое время GPU и не полный audio-to-photon. FFT выполняется до этого таймера. `dropped` включает устаревшие кадры при смене snapshot сцены. Результаты меняются с фоновой нагрузкой и энергорежимом; 16,67 мс — бюджет одного кадра при 60 FPS, не гарантия на любой машине.

Исходные данные: [native-integration.json](../artifacts/native-integration.json). Команда: `npm run native:build && npm run test:integration`.

## Чистое ядро

[TypeScript](../artifacts/browser-core-benchmark.json) и [Swift + Accelerate](../artifacts/swift-core-benchmark.json): 60 разогревающих + 300 измеряемых итераций на 240/1000/4096/8192 LED. Замер включает FFT и CPU-эффект, исключает генерацию demo PCM, отрисовку Canvas, GPU и сеть. Эти цифры нельзя напрямую сравнивать с Metal submission-to-completion: у него другой измеряемый участок и фиксированная стоимость submit.

Команды: `npm run bench`; `native/.build/release/neural-light-engine --benchmark`.

## 3D-предпросмотр и стеклянные панели

Отдельный замер интерфейса: Chrome 157, ANGLE Metal на Apple M5, viewport 1440×900. 800 мс прогрева и 180 интервалов requestAnimationFrame на вариант. Выполнялся браузерный рендер эффекта и новый WebGL-предпросмотр рабочего места; второй вариант каждого прогона — с открытой панелью настроек и backdrop blur.

| LED | Панель настроек | Средний FPS | Интервал p95, мс | Интервалы >25 мс |
|---:|---|---:|---:|---:|
| 240 | Закрыта | 60.00 | 16.7 | 0 |
| 240 | Открыта | 60.00 | 16.7 | 0 |
| 8192 | Закрыта | 60.00 | 16.8 | 0 |
| 8192 | Открыта | 60.00 | 16.8 | 0 |

Это короткий замер частоты браузерных кадров, не GPU timestamp, не измерение WKWebView и не задержка физической ленты. Статическая 3D-геометрия переиспользуется, цвета обновляются у шести источников; pixel ratio ограничен 1.5. При потере WebGL-контекста интерфейс автоматически использует Canvas-предпросмотр.

Исходные данные: [preview-benchmark.json](../artifacts/preview-benchmark.json). Повторить: запустить `npm run dev`, затем `node scripts/preview-benchmark.mjs` без параллельной сборки или тестов.

## Пройдено

- 17 Vitest-тестов: спектр и тишина, 120 BPM, валидация, blackout, timeline, геометрия, граф; переходы кадров, повторное переключение и отмена; поздняя активация демозвука после выключения/закрытия.
- 12 XCTest-тестов: Accelerate FFT и beat, DDP/DNRGB, маппинг, валидация, адаптивная политика, blackout; Metal/CPU с допуском 2/255; смешивание кадров и отмена переходов.
- 18 Playwright-сценариев: настройка/сохранение/открытие и отмена удаления, реальные изменения graph/mapping/timeline, browser mode, axe WCAG A/AA, 320/390/768 px, анимации, повторный Escape, фокус и Reduce Motion; независимость вида от топологии, панель источника/прослушивание на телефоне, fallback после потери WebGL-контекста.
- Интеграционный запуск: отказ неверному токену, бинарные RGB-кадры, DDP-фрагментация 1000 LED на UDP loopback, DNRGB loopback, отказ неверным параметрам, ограничение полосы и счётчики пропусков.
- `tsc` + Vite production build; Swift debug/release; самостоятельный `.app` открыт и визуально проверен с живым Metal, 60 FPS и определённым 120 BPM.
- Design lint / browser inspector: 0 FAIL; axe основного экрана: 0 violations.

## Что ещё надо измерить на оборудовании

Физическая задержка звука до LED, джиттер нескольких WLED, реальные потери Wi-Fi, лимиты конкретной ленты/прошивки, захват микрофона и ScreenCaptureKit после пользовательского разрешения, длительная стабильность и работа после сна/смены аудиоустройства. UDP send completion не подтверждает отображение. Инструкция: [аппаратный прогон](HARDWARE-CHECK.md).
